# Plan 2 implementation report — checkout 15-min countdown, guest-claim, cancellation

## Branch
`feat/checkout-countdown-guest-claim`

## Changes

### `_actions.ts`
- Added `import { cookies } from "next/headers"` and `import { getSessionCookieName } from "@/lib/flow-state"`.
- Extended `BookingDetails` interface with `expiresAt: string | null`, `secondsRemaining: number | null`, `reservationIds: string[]`.
- `fetchBookingDetails`: reads session cookie (`getSessionCookieName()` → dev=`qb.session_token`, prod=`__Secure-qb.session_token`) and forwards as `Cookie: qb.session_token=<value>` alongside the Bearer header. If no session (guest), cookie header is omitted.
- `fetchBookingDetails`: on 409 with `body.code === "NO_AVAILABILITY"` returns `{ data: null, error: "NO_AVAILABILITY" }`.
- `fetchBookingDetails`: parses `apiResponse.expiresAt`, `apiResponse.secondsRemaining`, `apiResponse.reservationIds` into `BookingDetails`.
- New `cancelBooking(token)` action: POST `/reservations/cancel-booking` with Bearer + forwarded cookie; returns `{ ok: boolean }`.

### `_lib/countdown.ts` (new)
- Pure helpers: `getRemainingSeconds(expiresAt)`, `isExpired(expiresAt)`, `formatMmSs(totalSeconds)`.
- Extracted so they are easy to unit-test without DOM.

### `_lib/lang.tsx`
- Added 6 new strings to both EN and ES: `holdNotice`, `holdExpired`, `holdRestartLabel`, `noAvailabilityTitle`, `noAvailabilityMessage`, `noAvailabilityBack`.

### `_components/booking-countdown.tsx` (new)
- Client component, props: `expiresAt`, `qbtBaseUrl`, `propertySlug`, `onExpire`.
- Ticks every 1s via `setInterval`. Derives remaining from `expiresAt` (server time is source of truth).
- Sticky banner: `sticky top-0 z-50`, blue (#1e3a8a), turns red (#dc2626) when < 2 min or expired.
- Start notice text alongside the timer while active.
- On expiry: shows `holdExpired` message + restart link → `{qbtBaseUrl}/properties/{slug}`.
- `onExpire` called once (guarded with a ref). Returns `null` if `expiresAt` is null (no banner).

### `_components/booking-page-client.tsx`
- Added `secureToken` and `qbtBaseUrl` props.
- Added `expired` state and `handleExpire` useCallback: sets `expired = true` and calls `cancelBooking(secureToken)` best-effort.
- Renders `<BookingCountdown expiresAt={...} propertySlug={...} qbtBaseUrl={...} onExpire={handleExpire} />` above `StepIndicator` (sticky, full-width).
- `handlePayment` returns early if `expired`.
- Pay button: `isDisabled={processingPayment || expired}`, grey background when expired.

### `page.tsx`
- Handles `bookingResult.error === "NO_AVAILABILITY"` → renders `<ErrorState>` with a message pointing back to the property.
- Passes `secureToken={secureToken}` and `qbtBaseUrl={process.env.NEXT_PUBLIC_QB_BOOKING_URL}` to `BookingPageClient`.

### `__tests__/countdown.test.ts` (new)
- Unit tests for `formatMmSs`, `getRemainingSeconds`, `isExpired` — 11 cases using fake timers.

### `__tests__/actions.test.ts` (new)
- Unit tests for `fetchBookingDetails`: parses hold fields, null/absent hold fields, NO_AVAILABILITY 409, generic 409.
- Mocks `next/headers` cookies (no session), `@/lib/flow-state`, env vars.

## Assumptions / constraints noted
- Restart link uses `NEXT_PUBLIC_QB_BOOKING_URL` (already in `.env`/`.env.production`) — no new env vars added.
- qb-back's authMiddleware is expected to read `qb.session_token` regardless of the `__Secure-` prefix — we always forward under the bare name `qb.session_token` per the brief.
- No beacon/unload handler added — qb-back's 15-min job handles abandonment.
- `cancelBooking` is best-effort (fire-and-forget, errors silently swallowed in the callback).
- NO_AVAILABILITY error page is a simple `<ErrorState>` (reuses existing component) rather than a dedicated i18n page — if the `noAvailabilityTitle/Message` strings need to be surfaced there, that's a follow-up.
