Documentacion SSO Auth Center

Esquema Prisma (Next.js 16) | Base de autenticacion centralizada para todas las apps.

Convencion: todos los campos camelCase del dominio se persisten en snake_case en BD via @@map y @map.

Beneficios SSO para el ecosistema: un solo identity store, auditoria consistente, revocacion centralizada, permisos por organizacion, soporte multi-proveedor (OAuth + password), y menor superficie de riesgo al compartir sesiones firmadas entre apps.

Convenciones de nombres (camelCase → snake_case)

Regla: fooBarBaz → foo_bar_baz en BD. Tablas y columnas se renombran con @@map y @map para mantener naming consistente y audit friendly.

  • Identificadores: userId → user_id, organizationId → organization_id.
  • Tokens y hashes: tokenHash → token_hash, nunca plain text.
  • Timestamps: expiresAt → expires_at (UTC).
  • Traza de cliente: userAgent → user_agent, ipAddress → ip_address.
No se almacena PII sensible en texto plano; contraseñas y tokens se guardan hasheados o encriptados.

Vision SSO y cohesion

El Auth Center es la unica fuente de identidad para todas las apps. Beneficios clave:

  • Ingreso unificado (OAuth y password) con propagacion de sesiones firmadas entre productos.
  • Control central de organizaciones, roles y revocaciones (cierre de sesion remoto, baja de cuentas comprometidas).
  • Auditoria consistente: IP, user-agent y cliente que origino la sesion.
  • Multi-tenant seguro: cada relacion usuario↔organizacion vive en member, evitando mezclas de datos.
  • Invitaciones trazables para onboarding controlado y con expiracion.

User

Identidad base y unica por persona. Aisla perfil de credenciales (account) y de pertenencia a organizaciones (member).

model User {
  id            String   @id @default(cuid())
  name          String
  email         String   @unique
  emailVerified Boolean  @map("email_verified")
  image         String?
  isSystemAdmin Boolean  @default(false) @map("is_system_admin")
  createdAt     DateTime @default(now()) @map("created_at")
  updatedAt     DateTime @updatedAt      @map("updated_at")
  sessions      Session[]
  accounts      Account[]
  members       Member[]
  invitations   Invitation[]
  @@map("user")
}

Por que? Separa identidad de autenticacion: puedes migrar de password a SSO sin tocar datos de perfil. Riesgos mitigados: evitar duplicados por email, controlar superadmins via is_system_admin.

Account (credenciales / OAuth)

Conecta usuario con proveedor de identidad (Google/Microsoft) o auth local. Permite multi-login sin duplicar perfil.

model Account {
  id        String   @id @default(cuid())
  userId    String   @map("user_id")
  accountId String   @map("account_id")
  providerId            String    @map("provider_id")
  accessToken           String?   @map("access_token")
  refreshToken          String?   @map("refresh_token")
  accessTokenExpiresAt  DateTime? @map("access_token_expires_at")
  refreshTokenExpiresAt DateTime? @map("refresh_token_expires_at")
  scope      String?
  idToken    String?   @map("id_token")
  password   String?
  createdAt  DateTime  @default(now()) @map("created_at")
  updatedAt  DateTime  @updatedAt      @map("updated_at")
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@map("account")
}

Por que? Evita lock-in de proveedor; puedes agregar OAuth sin tocar user. Tokens se guardan encriptados/hasheados. Escalabilidad: multiproveedor sin cambiar el dominio.

Session

Sesiones firmadas con trazabilidad. Permiten logout centralizado y auditoria.

model Session {
  id        String   @id @default(cuid())
  userId    String   @map("user_id")
  token     String   @unique
  expiresAt DateTime @map("expires_at")
  ipAddress String?  @map("ip_address")
  userAgent String?  @map("user_agent")
  activeOrganizationId String? @map("active_organization_id")
  clientId  String?   @map("client_id")
  revokedAt DateTime? @map("revoked_at")
  createdAt DateTime  @default(now()) @map("created_at")
  updatedAt DateTime  @updatedAt      @map("updated_at")
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@map("session")
}

Por que? Auditoria (IP/UA), control de organizacion activa para UX contextual, cierre remoto (revoked_at) en incidentes.

Verification (tokens de verificacion)

Tokens temporales para verificacion de email, magic links y reset de password. Se almacenan hasheados.

model Verification {
  id         String   @id @default(cuid())
  identifier String
  value      String
  expiresAt  DateTime @map("expires_at")
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt      @map("updated_at")
  @@map("verification")
}

Por que? Evita dependencia de proveedores de correo como fuente de verdad; permite invalidar tokens al instante y auditar usos.

Organization

Representa tenant/unidad de negocio. Todo permiso se deriva de pertenencia en member.

model Organization {
  id        String   @id @default(cuid())
  name      String
  slug      String   @unique
  logo      String?
  metadata  String?
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt      @map("updated_at")
  members       Member[]
  invitations   Invitation[]
  @@map("organization")
}

Por que? Multi-tenant limpio: separa datos y roles. Valor: permite que un usuario pertenezca a varias orgs con roles distintos.

Member (roles por organizacion)

Puente User↔Organization con rol efectivo. Soporta multi-rol multi-org sin duplicar usuarios.

model Member {
  id             String   @id @default(cuid())
  userId         String   @map("user_id")
  organizationId String   @map("organization_id")
  role           String
  createdAt      DateTime @default(now()) @map("created_at")
  updatedAt      DateTime @updatedAt      @map("updated_at")
  user         User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  organization Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)
  @@unique([userId, organizationId])
  @@map("member")
}

Por que? Evita clonar usuarios por tenant, habilita RBAC por org y controles de acceso claros. La unique comp impide roles duplicados en la misma org.

Invitation

Onboarding seguro y auditable para agregar miembros a una org.

model Invitation {
  id             String   @id @default(cuid())
  organizationId String   @map("organization_id")
  email          String
  role           String
  status         String
  tokenHash      String?  @map("token_hash")
  inviterId      String   @map("inviter_id")
  expiresAt      DateTime @map("expires_at")
  createdAt      DateTime @default(now()) @map("created_at")
  acceptedAt     DateTime? @map("accepted_at")
  organization   Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)
  inviter        User         @relation(fields: [inviterId], references: [id], onDelete: Cascade)
  @@map("invitation")
}

Por que? Elimina altas manuales; define rol desde el envio y evita reuso de tokens (hash). Expiracion controla riesgo de invitaciones abandonadas.
